# 项目协作规则

## 接口文档持续维护

用户要求：每次在本项目执行任务时维护接口文档，保留旧版本，使用专门文件夹存储。

- 开始任务前读取 `docs/api/README.md` 和其中的最新交接说明，对照 `server/index.ts`、`server/schemas.ts`、`shared/types.ts` 及本次涉及的流程代码。
- 每次任务结束前新增一个接口交接版本，包括只读检查、文档工作和接口无变更的任务。接口未变化时明确记录“已核对，无接口变更”，说明核对范围和实际验证；不要把未执行的测试写为通过。
- 新版本放在 `docs/api/versions/YYYY-MM-DD-HHmmss/`，时间使用 `Asia/Shanghai`。同名目录已存在时追加序号，不复用、覆盖、移动或删除任何已有版本。
- 每个版本包含完整的 `frontend-handoff.md`、`api-examples.http`、`fixtures/frontend.mock.json`、`shared/types.ts`、`server/schemas.ts`、供说明引用的 `src/App.tsx`、版本说明 `README.md` 和校验清单 `manifest.json`。引用的代码快照供阅读，不作为独立可运行工程。
- 历史版本全部只读。原有 `docs/frontend-handoff.md`、`docs/api-examples.http`、`docs/fixtures/frontend.mock.json` 也作为首次交接原件保留，不再覆盖。新内容只写进本次新建的版本目录。
- 保留 `.gitattributes` 对 `docs/**` 的 `-text` 设置，避免 Git 自动换行转换改变归档字节和 SHA-256 校验值。提交前核对暂存区中的文件与清单一致。
- 新文档以最新版本为起点，按实际代码更新；确认版本内的相对链接和样例引用有效。接口行为、输入约束、响应、SSE 事件、错误处理、前端适配事项和验收步骤应同步维护。
- 版本说明记录北京时间、任务内容、代码基线、相对上一版本的变化、兼容性、前端是否需要适配以及实际验证结果。`manifest.json` 记录版本文件的 SHA-256 和所核对源文件的 SHA-256，不包含凭证或环境变量值。
- 更新 `docs/api/README.md` 的最新版本入口，并追加历史索引行；保留已有索引记录。项目根 README 指向这个固定入口，不直接指向会过时的单一版本。
- 密钥、签名 URL、临时图片访问地址、原始知识库和真实私有资料不得写入交接版本；样例优先使用明确标识的纯模拟数据。
- 最终回复提供本次版本路径，说明接口是否变化。本地归档不自动等于 Git 提交或推送；只有当前任务已授权时才执行相应远端操作。

## 前后端分工

后端主要维护 `server/`，前端主要维护 `src/`。修改共享类型、输入校验或接口行为时，同步维护本次交接版本并列出前端适配事项。
