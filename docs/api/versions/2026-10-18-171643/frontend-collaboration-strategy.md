# 前端协作与接口对接策略

> 当前状态：本文件保留需求与工具研究背景。当前工作区已有大纲、设置、任务选项及渲染路由，协议以 [当前接口说明](frontend-handoff.md) 为准，不能据旧规划认定这些能力尚未编码。

我们采用同仓库分支开发，先用模拟数据完成前端，再在我的电脑上进行首轮真实联调。我负责后端和 AI 工作流，你负责前端设计与交互；接口字段以交接文档和共享类型为共同约定。

## 分工

| 我负责后端 | 你负责前端 |
| --- | --- |
| 模型接入、ima 检索、产品事实和图片读取 | 任务表单、平台选择、连接状态与来源展示 |
| 策划、图文生成、审稿和定向修订 | 双平台预览、进度、修改入口、停止与重试 |
| 输入校验、错误响应、接口文档和模拟数据 | 原文引用跳转、配图编排、核验面板、会话历史和导出 |

你可以调整整体视觉、布局和组件结构。涉及共享类型、字段名称、枚举或接口行为的变化，我们先对齐，再同步代码与新版本文档。

## 第一阶段 拉取资料并完成页面

首次拉取交接分支可以使用：

```powershell
git clone --branch backend/api-handoff https://github.com/BayesBai/Leo.git
cd Leo
npm ci
git switch -c frontend/workbench
npm run dev
```

已有本地仓库时先保存自己的改动，再按交接说明切换分支。后续由你在前端分支提交，通过 PR 集成。

先阅读[接口说明](frontend-handoff.md)，使用[模拟数据](fixtures/frontend.mock.json)设计页面。优先完成任务表单、双平台预览、事实依据、配图编排和核验面板，再补加载、空数据、待确认、待修正及错误状态。

这一阶段不需要模型密钥或原始知识库。模拟数据需要由前端自行接入，当前没有内置 Mock 启动开关；模拟产品和任务 ID 不提交到真实生成接口。

阶段交付物是可运行的页面、主要界面截图，以及已完成和待联调功能的列表。

## 第二阶段 接入真实接口

建议把请求与 SSE 解析集中到 `src/api/client.ts`，页面组件只消费结构化数据和状态。这个模块是建议新增的前端组织方式，当前请求逻辑在 `src/App.tsx` 中，可从现有实现提取。

| 顺序 | 接口或数据 | 需要实现的行为 |
| --- | --- | --- |
| 1 | `GET /api/status`、`GET /api/products` | 分别加载连接状态和型号目录，产品 ID 来自目录 |
| 2 | `POST /api/connections/verify` | 使用正式 ima 模式时验证连接，显示实际结果 |
| 3 | `POST /api/generate` | 发送任务 JSON，读取 SSE 进度及最终结果 |
| 4 | 结果中的事实 ID、图片 ID 和图片 URL | 正确关联原文、限定条件、图片与插入位置 |
| 5 | `POST /api/revise` | 使用最新 `result.id` 修改任务，成功后保存新 ID 并同步返回的表单条件 |

生成和修改使用 POST 加 SSE。前端处理 `progress`、`result`、`needs_input`、`error` 四类事件；HTTP 200 只表示流建立，仍可能报错。收到结果后，还需单独展示 `passed`、`needs_attention` 或 `blocked` 的内容审核状态。

停止通过 AbortController 关闭当前请求。生成失败或取消时保留上一份完整成稿，允许再次提交。`GET /api/sample` 只是可选的本地示例，缺少本地知识库时可能失败，不应阻塞整个页面。

阶段交付物是状态、目录、生成、原文与配图、修改这一条完整操作流程，以及对应的错误和取消处理。

## 第三阶段 真实联调与验收

首轮把你的前端改动集成到我的电脑，由我提供有权使用的资料和后端配置，在项目根目录启动 `npm run dev`。现有服务同时提供前端和 API，页面统一请求相对路径 `/api/...`；模型与 ima 凭证保留在后端。

你在另一台电脑上打开我的 `127.0.0.1:9753`，实际上会访问你自己的电脑。如果之后需要两台电脑实时直连，我们另行确认可达的测试地址和代理配置；推送代码本身不会部署共享后端。

验收先跑完整流程：填写任务 → 生成双平台内容 → 查看原文与图片 → 修改 → 查看核验 → 导出。

随后检查以下情况：

- 必填信息缺失、任务过期或并发受限时，提示清楚并恢复可操作状态。
- SSE 内报错、连接中断或主动停止后，可以重新提交。
- 图片缺失或过期时显示占位与提示，其他页面仍能使用。
- 审核提醒在页面和导出中保留，模拟与真实来源标识准确。
- Markdown 导出包含场景判断、知识库依据、图文软文、核验结果四部分，不包含密钥、签名 URL、临时图片地址和内部编号。
- 窄屏下任务、内容和依据都可访问，无页面横向溢出。

## 提交与沟通约定

你主要修改 `src/`，我主要修改 `server/`；共享类型、依赖和接口行为由我们共同确认。每完成一个可联调功能就提交一次 PR，注明对应接口文档版本、完成内容、截图、实际验证结果和剩余问题。

遇到接口问题，提供请求路径、脱敏请求体、HTTP 状态、最后一个 SSE 事件和页面现象，便于共同定位。密钥和完整知识库不进入代码或讨论记录。

每次项目任务都会在 `docs/api/versions/` 新增交接版本，旧版保留。双方以 `docs/api/README.md` 的最新入口为准；新增版本需要提交到团队仓库后，对方才能拉取。

这份策略按三个阶段推进，每阶段通过后进入下一阶段。第一步先用 15 分钟确认分工、字段和主页面范围，然后各自开始开发。
