## 文案为何容易相似

模型模式确实逐渠道调用写作，并传入各自PLATFORM_POLICIES；不能据此说完全没有渠道适配。但四个渠道共同使用intro、blocks、cta、tags的内容容器。新流程使用的OUTLINE_WRITER_PROMPT强调按已确认结构填正文，渠道差异主要依靠平台配置和字数描述，没有各渠道的正例、段落功能、明显不同的表达目标或跨渠道相似度验收。旧WRITER_PROMPT中有更具体的逐渠道说明，新大纲写作路径没有直接使用该段。

大纲生成同样共用提示与段落结构；如果确认前已经相似，后续写作和渲染都无法主动重组已确认结构。渲染阶段有意保留审核稿件，不应偷偷重写来补救策划不足。

本地规则模式更明显：buildStrategies先统一筛事实，再为渠道套语气和结构；公众号、小红书和海报通常沿用同一组卖点，朋友圈取其中一个。多个段落的标题来自同一个factTopic，选购清单、核对配置与到店等句式反复出现。审核主要检查事实、引用、图数和长度，没有专门判断不同渠道是否在选题、叙事与构图上有足够差异。

## 本次实际对照及限制

用现有纯模拟fixture，分别为四个单渠道离线调用buildStrategies和buildDemoDrafts，没有访问产品库。公众号、小红书与海报选择相同两个模拟事实，朋友圈取其中一个；事实段落标题均落到同一个通用主题，附加清单/决策段不同。详见[模拟对照摘要](channel-homogeneity-audit.json)。这证明规则模式的选择复用机制，不是对用户当前某份真实模型输出的相似度测量。

本次没有取得用户当前页面作品，不能断定其使用的是demo还是live。真实模式同质化的判断是基于共享提示、结构和版式代码的原因分析，不把静态审计写成四渠道真实生成验收。

## 建议下一步实现（未实施）

保留同一事实依据，为四个渠道分别定义内容组织与视觉组织；共享渲染引擎没有问题，但构图不应只改尺寸和配色。

| 渠道 | 应强化的内容与版式 |
| --- | --- |
| 公众号 | 一个选购问题、论证与场景解释、分节长文、穿插图文及独立封面 |
| 小红书 | 封面选题、可收藏清单、逐页展开、明确页型变化及互动结尾；不编造亲测 |
| 朋友圈 | 销售员自然沟通、一个到店理由、简短咨询入口；文字与图片卡分工，主图或拼图构图 |
| 海报 | 主标题、副标题、产品主视觉、1至3个短卖点、到店信息和必要条件分槽；不把全文塞入同一text |

需要在大纲确认前完成渠道策划区分，确认后保持结构承诺。增加同一Brief下的多渠道对照验收，分别检查叙事、卖点取舍、CTA和版式；事实一致本身不是缺陷，不应为去重改变产品参数或必要条件。当前八个模板ID不代表八种实质独立构图。仅换文案模型无法修复共用的固定布局。
