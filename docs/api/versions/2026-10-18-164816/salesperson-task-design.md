# 面向销售员的任务输入设计

> 当前状态：本文件保留需求与工具研究背景。当前工作区已有大纲、设置、任务选项及渲染路由，协议以 [当前接口说明](frontend-handoff.md) 为准，不能据旧规划认定这些能力尚未编码。

状态：待实现设计。实际操作者固定为销售员，目标人群表示销售员本次希望触达的客户。场景、人群与发布平台分别记录，按每次营销任务变化。

依据：本地赛题手册第 4 页的建议业务场景与平台场景，以及第 5 页的任务输入和场景理解要求；已核对文本及完整页面图像。以下 ID、字段结构和交互组织是本项目设计，手册给出的是建议示例而非封闭枚举。原始 PDF 与知识库不随本交接包发布。

## 基础业务场景与推荐客户

| 业务场景 | 推荐客户人群 | 可考虑的内容方向 |
| --- | --- | --- |
| 开学季 | 大学新生、家长 | 学习任务、便携需求、续航需求、设备协同 |
| 职场办公 | 商务人士、移动办公者 | 会议与差旅、文档处理、多任务协同、安全需求 |
| 内容创作 | 设计创作者、摄影创作者、视频创作者 | 屏幕需求、性能需求、素材流转、创作流程 |
| 家庭换新 | 家庭用户、旧机换新者 | 易用性、家庭共同使用、数据迁移、长期使用 |
| 企业采购 | 中小企业、团队采购 | 部署管理、稳定性、服务信息 |
| 门店到访 | 附近潜在顾客 | 一个核心卖点、到店体验理由、咨询引导 |
| 新品首发 | 关注新品的用户 | 新品变化、适合人群、选购建议 |
| 节日营销 | 送礼人群、家庭购机人群 | 礼赠与家庭场景、选择建议 |

推荐人群用于缩小选项范围，不是不可修改的绑定。开学季可分别面向新生或家长，两者应产生不同的决策关注点；门店到访也不限定客户只能是某一类人。保留自定义场景与自定义人群。

内容方向属于用户需求，不能证明任一型号具有对应能力。续航、协同、迁移、性能、安全和服务等产品描述仍需从具体型号的有效产品证据中取得。

## 保留三步选择流程

第一步选产品。第二步选业务场景，并在同一步显示客户人群和本次营销目标。第三步选发布平台。随后填写可选补充要求，再进入大纲生成、修改、确认以及正文生成。

```text
产品
  → 业务场景 ＋ 客户人群 ＋ 营销目标
  → 发布平台
  → 补充要求
  → 大纲修改与确认
  → 正文生成、核验和导出
```

业务场景切换后展示推荐人群，由销售员确认；不要静默覆盖销售员已填写的客户。信息不足时追问补充。把自由提示词输入页命名为补充要求，让销售员描述语气、重点和用途，系统提示词仍由后端维护。

接入变量在设置阶段配置并验证，配置完成后销售员日常可以直接进入任务。配置人员与使用者的角色权限若后续需要区分，另行设计；当前单账号 Demo 没有新增管理员权限或登录能力。

## 字段含义与现有接口映射

| 概念 | 本次含义 | 当前实现或计划 |
| --- | --- | --- |
| 操作者 | 销售员 | 产品固定使用身份，可进入系统角色说明；当前 Brief 没有新增 operatorRole 字段 |
| 产品 | 本次推广的具体型号 | 沿用 productId |
| 业务场景 | 开学季、职场办公等 | 目前 scene 是字符串；拟新增的场景 ID 需在协议确定后实现 |
| 客户人群 | 大学新生、家长、商务人士等 | 沿用 audience，其值不是销售员 |
| 营销目标 | 到店体验、咨询等 | 沿用 goal，默认或建议值应对销售员可见 |
| 购买阶段 | 客户目前了解或决策到哪一步 | 沿用 buyingStage，必要时补充询问 |
| 发布平台 | 公众号、小红书、门店朋友圈、门店海报 | 沿用 platforms 的四个枚举 |
| 补充要求 | 销售员对文案的额外要求 | 沿用 instructions |

例如同一销售员推广同一型号，选择开学季与大学新生时可以讨论学习与携带需求；换成家长时，改为帮助家长核对适用需求与配置；再换职场办公与移动办公者，则围绕差旅和工作任务组织内容。所有卖点仍需有原文支持。

## 前后端分工调整

后端负责人维护场景与人群选项、稳定 ID、业务含义、校验和提示词策略；前端队友负责三步页面、推荐人群联动、自定义输入、确认状态与补充要求输入。双方共同确认选项数据结构，避免前后端各自维护不同枚举。

建议后续提供统一的任务选项接口，返回场景、推荐人群、可自定义标记和平台规则。本版提供的是 [选项结构草案](fixtures/sales-task-options.proposed.json)，没有新增可调用的选项路由，也没有修改当前共享类型或 Mock 适配方式。

这份 JSON 是需求与选项草案，不是产品事实库，不含真实客户信息，也不是现有后端接口的返回记录。原有 frontend.mock.json 继续只用于当前运行版页面布局。

## 与大纲确认流程衔接

大纲记录最终确认的产品、场景、客户人群、目标、平台与补充要求。销售员调整其中任何会影响内容的条件时，新版本大纲需重新校验和确认；正文生成使用已经确认的任务与大纲快照。

## 设计验收项

- 同一销售员可以切换不同业务场景和客户人群。
- 同一场景可以选择多个不同的客户类别，推荐值允许修改或自定义。
- 页面不会把销售员固定身份填入 audience。
- 未确认客户人群时，不能把不完整信息静默变成已确定条件。
- 更换人群和场景后，大纲的切入点与卖点顺序发生实质变化。
- 更换平台后，标题、结构、语气、图片数量和行动引导按平台调整。
- 情境需求不被当作产品能力，产品描述仍绑定证据。
