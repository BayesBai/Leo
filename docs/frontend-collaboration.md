# 前后端协作与本地联调

本页是两人当前执行的协作约定。后端功能基线为 `5008332`，本轮开始时的最新协议为 `2026-10-18-171643`；本轮及以后新增交接统一从[接口版本固定入口](api/README.md)查阅，不能根据旧策略中的“待实现”判断当前功能。历史交接与最初交接原件保持只读。

本轮聚焦本地开发与联调，实际验证结果见最新交接。后续云服务器、评委访问方式和共享环境另行讨论；Git 拉取或合并本身不会部署应用。

## 分工与集成

| 负责人 | 主要范围 | 交付责任 |
| --- | --- | --- |
| 前端 | `src/` 的页面、交互、状态和 API 适配 | 门店人员可完成任务；展示来源与审核；取消、失败和过期可恢复；复制及下载遵守审核状态 |
| 后端 | `server/`、模型、ima、检索、事实核验和渲染 | 提供真实来源与原图；校验输入、版本和资源归属；返回可定位错误；维护接口交接 |
| 共同确认 | `shared/types.ts`、输入校验、接口行为、依赖与构建配置 | 修改前对齐影响，代码、模拟数据和新交接版本一起更新 |

建议以 `main` 作为团队集成基线，两人各自使用功能分支，经 PR 合入；这是团队约定建议，不表示本轮已经切换默认分支、推送或合并远端。已有 `frontend/workbench`、`backend/api-handoff` 分支按实际 Git 状态继续使用，不在未保存改动时直接切换。

每项可联调能力单独交付。后端接口变化优先给出输入、返回、状态和示例；前端在同一协议下完成交互，再共同进行真实联调。不要在功能分支各复制一套共享类型，也不要从历史阅读快照中拼装运行工程。

## 面向门店的最小流程

1. **填写任务**：选择产品、客户与场景，选择 1–4 个不同渠道；营销目标提供默认值，补充要求折叠。接入设置是独立入口，不要求每次生成先填写密钥。
2. **确认大纲**：先读标题、内容切入和段落摘要，需要时展开编辑、调整要点与配图。保存或 AI 修改后产生新版本，必须确认当前版本后才能生成正文。
3. **文案与成品**：查看各渠道文案、产品原图、来源、策略及审核，生成视觉成品，复制或下载；修改任务条件应重新生成大纲。

新流程调用大纲、确认及 `generate-from-outline` 接口，不用旧的直接生成接口绕过确认。HTTP/SSE 和资源访问集中在 `src/api/`；`src/api.ts` 保留页面兼容入口，页面不自行复制 SSE 解码或 Mock 判断。

前端始终区分本次大纲 ID/版本、正文 ID/修订及成品渠道/模板。更换条件、正文、标题或模板时不能继续显示旧成品为当前结果；取消或失败保留已保存内容，并明确说明本次没有完成。

审核为 `blocked` 时，只能展示带标记预览，禁止复制、正式下载和 ZIP；`needs_attention` 保留待确认项，下载不代表审核或发布验收通过。产品图片使用接口返回的当前型号原图，不生成设备外观、不拉伸、不复制图片凑数量。事实、价格、权益或图片来源不足时显示问题，不用占位数据冒充真实结果。

## 本地开发与纯模拟

需要 Node.js 22.12 或更新版本，在项目根目录运行：

```sh
npm ci
npm run dev
```

默认打开 `http://127.0.0.1:3000`，实际端口以终端为准。开发命令启动 Express，并在同一服务内挂载 Vite，页面及 `/api` 同源，无需另开 Vite 进程或配置 CORS。

纯模拟前端联调打开 `http://127.0.0.1:3000/?mock=ok`。无需模型密钥、ima 凭证或原始知识库；页面明确标记“纯模拟”，配置验证、JSON、SSE 和资源请求由统一前端 transport 模拟，不发送到真实 `/api`，不调用模型或 ima。模拟 ID 和图片只用于界面验证。

可将 `mock` 参数换成 `blocked`、`needs_input`、`error`、`empty`、`slow`、`expired`、`conflict`、`disconnected` 或 `insufficient-images`，分别检查阻断、补充输入、失败、空目录、慢请求/取消、过期、版本冲突、断流和素材不足。删除参数并刷新回到真实接口模式；不要把 Mock 页面截图作为真实运行证据。

需要真实视觉渲染时先运行 `npm run setup:render` 安装 Chromium。模型、ima 与获授权的本地资料按根 [README](../README.md) 配置；新克隆不自带密钥或原始知识库。没有资料时可以看公开型号目录，不能据此声称完成产品检索与生成。

若另开独立 Vite 服务，才需要把 `/api`（包括图片与成品）代理到实际后端地址，并保留 Host：

```ts
server: {
  proxy: {
    '/api': { target: 'http://127.0.0.1:3000', changeOrigin: false }
  }
}
```

写入接口校验 Origin 与 Host，不直接跨端口请求。另一台电脑上的 `127.0.0.1` 指向那台电脑；本轮本机地址不作为队友共享地址。

## 模式与验收证据

| 运行方式 | 文案与审核 | 资料 | 可以证明什么 |
| --- | --- | --- | --- |
| URL `mock` 纯模拟 | 前端模拟响应与状态 | 明确标识的虚构夹具和示意图 | 页面、流程与异常交互；不证明后端、模型或 ima 可用 |
| `demo + local` 规则演示 | 规则大纲、规则正文与规则检查 | 获授权的本地产品资料和原图 | 本地后端闭环；不证明模型调用或 ima 读取 |
| `live + local` 模型创作 | 实际模型策划、写作和审稿 | 获授权的本地资料 | 模型与本地证据流程；不证明 ima 端到端 |
| `live + ima` 正式接入 | 实际模型与核验流程 | 账号有权读取的指定 ima 共享库 | 经当次实际运行后，可作为比赛接入与事实来源验收 |

模型已配置、模型验证成功、ima 已配置、ima 验证成功、当次资料检索成功、内容审核通过、平台实际发布分别记录。真实调用失败时保留失败原因，不自动换成 Mock、规则或本地资料并显示为成功。规则演示不能与纯模拟混称，历史调用也不替代本轮实际验证。

双方合并前至少验证所改流程：任务 → 编辑/保存/确认大纲 → SSE 正文 → 审核 → 成品。按变更补充缺信息、取消、断流、版本冲突、过期、图片不足与审核阻断；同一产品换人群应改变切入点，换平台应改变结构、语气、配图和行动引导。真实 ima 需单独完成检索、来源及图片型号核对，未执行或额度不足时如实记为待验收。

## 每次 PR 的交接

使用仓库 [PR 模板](../.github/PULL_REQUEST_TEMPLATE.md)，至少附：代码提交 SHA、对应新交接版本、主要界面截图或录屏、实际已测/未测项目与遗留问题。截图应标明运行模式并隐去凭证、签名 URL 和私有资料。

接口有无变化都按 [AGENTS.md](../AGENTS.md) 新增完整归档；版本时间使用北京时间，旧版本不覆盖。无变化写“已核对，无接口变更”，列出核对范围。接口变化同步类型、校验、样例和前端适配事项；入口更新与版本内容同次交付。归档路径不等于运行 API 增加版本前缀。

故障交接提供代码 SHA、交接版本、运行模式、请求路径、脱敏输入、HTTP 状态、最后一个 SSE 事件和页面现象；不发送 API Key、完整知识库或临时资源地址。只提交允许交付的源码与模拟数据，不提交 `.env.local`、原始资料、缓存和真实生成产物。

常规检查按实际变更执行并报告结果：

```sh
npm run check
npm test
npm run build
```

这些命令不包含真实模型、ima 或平台发布验收。前端还需浏览器检查主要流程与窄屏，后端还需验证变更对应的真实接入；只写实际执行结果，不把建议检查写成已通过。提交前核对归档 `manifest.json` 与暂存文件一致，并保留 `.gitattributes` 的 `docs/** -text` 设置。
